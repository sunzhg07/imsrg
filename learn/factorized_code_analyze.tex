\begin{abstract}
\noindent
The M-scheme \emph{unfactorized} 3-operator formulas
(Sec.~\ref{sec:unfact}) are the leftover gold.
They are locked as printed and have been checked, for both hermiticities of
$\Omega$ and for scalar and tensor $\Omega$, against
$\mathtt{GetMscheme}(\mathtt{comm223st}\to\mathtt{comm231tts}
+\mathtt{comm232tts}+\mathtt{comm132tts})$
(and the scalar $ss$ path when $\lambda=0$).
Section~\ref{sec:fact} prints the \emph{factorized} M-scheme that
\codename{UnitTest::Mscheme\_fact\_*} / \codename{Mscheme\_chi\_*} actually
evaluate (slots, occupations, leftover CG), not an older compact print.
Section~\ref{sec:jscheme} writes the J-scheme AMC formulas that
\codename{FactorizedDoubleCommutator\_eths.cc} implements.
Section~\ref{sec:code} is the scalar packed path in
\codename{FactorizedDoubleCommutator.cc} (default $h_\Omega=-1$);
it is not leftover gold.
Unreduced scalar $\Omega$ is \codename{MakeReduced} on entry
(\codename{ReducedRMEView}) in \codename{comm223st}, leftover
\codename{*tts}, and ethS, then takes the same tensor leftover path.
\end{abstract}

\section{Conventions}
\label{sec:conv}
% =============================================================================

Two-body matrix elements are antisymmetrized:
$O_{pqrs}=-O_{qprs}=-O_{pqsr}=O_{qpsr}$.
Hermiticity (when it holds) is
\begin{equation}
  O_{pqrs}=h_O\,O_{rspq},\qquad h_O=\pm 1.
\end{equation}
We write $\Omega$ for the generator (code: \codename{Eta}) and $\Gamma$ for
the Hamiltonian-like operator.
The double commutator contributes to one-body $f$ and two-body $\Gamma$ pieces
of the output $Z$.
Occupation numbers: $n_a\in\{0,1\}$, $\bar n_a=1-n_a$.
$\hat P_{ij}$ exchanges free indices $i\leftrightarrow j$.
\codename{GetMschemeMatrixElement\_*} is always the physical (unreduced) $m$
ME. AMC \codename{reduce=true} is a reduced RME; default scalar
\codename{IsReduced()=false} is unreduced.

\paragraph{Leftover CG.}
When two rank-$\lambda$ $\Omega$ couple to a leftover scalar, the m-scheme
code multiplies
\begin{equation}\label{eq:cg-leftover}
  C_\lambda(\mu)
  =\CGleftover
  =(-1)^{\lambda-\mu}/\hat\lambda,
  \qquad
  \mu=\tfrac12(M_{\mathrm{bra}}-M_{\mathrm{ket}})\ \text{of the first $\Omega$}.
\end{equation}
(\codename{cg\_OmOm0} in \codename{UnitTest.cc}.) For $\lambda=0$, $C_0=1$.
This CG sits on every $[\Omega\times\Omega]^{(0)}$ intermediate
($\chi^{\alpha,\gamma,\delta,\varepsilon,\eta,\theta}$) and on every leftover
fold that multiplies a second $\Omega$
($f^{\mathrm{II}}$, $\Gamma^{\mathrm{II,IV_a,IV_b,IV_c}}$, III$_b$ 3-op).
It is \emph{not} inside $\Omega\times\Gamma$ or $\Gamma\times\Omega$
intermediates ($\chi^{\beta,\zeta,\Omega\Gamma,\iota,\kappa,\lambda}$).

Pandya (particle--hole) and cross-coupled (CC) forms used below follow the
code conventions in Sec.~\ref{sec:transforms}.

\subsection{Verification chain (no tune)}
\label{sec:verify-chain}

The intended workflow---especially for tensor / TTS ethS diagrams---is:
\begin{enumerate}
  \item \textbf{M-scheme equation is golden.}
    Unreduced physical $\langle m|\cdots|m\rangle$
    (Sec.~\ref{sec:unfact}, or the AMC analyze string with the correct
    scalar projection when the LHS is scalar and factors are tensors).
    Compare J-scheme results to m only via
    \codename{UnitTest::GetMschemeMatrixElement\_*}; do not invent m-scheme
    phases or partner swaps to force a match.
  \item \textbf{AMC derives DIRECT and Path~B} from that string
    (ordinary-channel RME vs Pandya / intermediate factorization).
    If DIRECT and Path~B disagree, fix the AMC inputs or the angular
    reduction---not the m-scheme oracle.
  \item \textbf{Code implements the AMC formulas literally}
    (\codename{tts\_*} reference = DIRECT; ethS factorized = Path~B).
    They must match m and each other \emph{with no tune}: no extra overall
    phases, hat factors, or index swaps added ``to match the other J path.''
\end{enumerate}
A mismatch means a bug in AMC packaging or in the code transcription.
The $f^{\MyRomanNum{2}}$ ethS outer
$(-1)^{(j_2+1)/2}$ (Sec.~\ref{sec:code-fII}) is an example of a forbidden
tune: it made DIRECT$\equiv$Path~B while both disagreed with m.

\section{Transforms used in the code}
\label{sec:transforms}
% =============================================================================

Forward Pandya (normal $\to$ Pandya), as implemented
(\coderef{1289--1296}):
\begin{equation}\label{eq:pandya-fwd}
\bar O^{J}_{a\bar b\,c\bar d}
  =-\sum_{J'}(2J'+1)\,
   \sixj{j_a}{j_b}{J}{j_c}{j_d}{J'}\,
   O^{J'}_{a\,d\,c\,b}.
\end{equation}
Inverse Pandya for a single $(1-\hat P_{ij})$ (used for $\chi^\eta\to$ normal,
\coderef{1380--1470}):
\begin{equation}\label{eq:pandya-inv-1P}
O^{J}_{ijkl}
  =-(1-\hat P_{ij})\sum_{J'}(2J'+1)\,
   \sixj{j_i}{j_j}{J}{j_k}{j_l}{J'}\,
   \bar O^{J'}_{i\bar l\,k\bar j}.
\end{equation}
Inverse Pandya with full $(1-\hat P_{ij})(1-\hat P_{kl})$ (used for
$\Gamma^{\MyRomanNum{3}_b}$, \coderef{2719--2849}), schematically
\begin{equation}\label{eq:pandya-inv-2P}
O^{J}_{ijkl}
  =-(1-\hat P_{ij})(1-\hat P_{kl})\,(-1)^{J+j_i+j_j}
   \sum_{J'}(2J'+1)\,(-1)^{J'+j_i+j_k}\,
   \sixj{j_j}{j_i}{J}{j_k}{j_l}{J'}\,
   \bar O^{J'}_{j\bar l\,k\bar i},
\end{equation}
with all four exchange channels $(jl,ki)$, $(ki,jl)$, $(il,jk)$, $(jk,il)$
accumulated explicitly in the code.

Pandya$\to$CC recoupling for $\chi^\eta$
(\codename{barCHI\_III\_RC}, \coderef{1749--1841}):
\begin{equation}\label{eq:RC}
\begin{aligned}
\overline{\overline\chi}{}^{\eta\,J}_{a\bar b\,c\bar d}
&=-\sum_{J'}(2J'+1)\,(-1)^{j_b+j_c+J'}

\section{Hermiticity assumptions and known gaps}
\label{sec:herm}
% =============================================================================

Throughout \codename{FactorizedDoubleCommutator.cc},
\begin{equation}
  h_\Omega=\begin{cases}+1&\Omega\text{ Hermitian}\\-1&\Omega\text{ anti-Hermitian}\end{cases},
  \qquad
  h_\Gamma=\begin{cases}+1&\Gamma\text{ Hermitian}\\-1&\Gamma\text{ anti-Hermitian}\end{cases},
\end{equation}
and often $h_Z=h_\Gamma$.

\subsection{Standard IMSRG case (code default path)}
Most packed products and ``$A+A^{T}$'' shortcuts are derived for
\begin{equation}
  h_\Omega=-1,\qquad h_\Gamma=+1
  \qquad\Rightarrow\qquad h_\Omega h_\Gamma=-1.
\end{equation}
In that case the formulas of Sec.~\ref{sec:fact} match the unfactorized
Sec.~\ref{sec:unfact} and the present implementation.

\subsection{What still needs care for general $(h_\Omega,h_\Gamma)$}
\begin{enumerate}
  \item \textbf{$f^{\MyRomanNum{2}}$.}
    Must keep $h_\Omega h_\Gamma$ on the second $\Omega$ string
    \eqref{eq:fact1b}. The code path \coderef{361--362} uses
    $\chi_{de}\Omega-\,h_Z\chi_{ed}\Omega$ with $h_Z=h_\Gamma$; this is
    equivalent for $h_\Omega=-1$ but should be checked if both signs flip.
  \item \textbf{$\Gamma^{\MyRomanNum{2}}$.}

    at the same $m$.
  \item \textbf{$\Gamma^{\MyRomanNum{4}_a}$.}

  \item \textbf{$\Gamma^{\MyRomanNum{4}_b}$.}
